Privacy Policy

Last updated: November 9, 2026

This policy describes how the CFI Presentations desktop application handles information when it is run on a user's computer.

1. How the application works

CFI Presentations is designed to run locally on the user's computer. Lesson inputs, uploaded reference documents, generated lesson files, project data, and application settings are stored locally by default in the application data folder. The application does not operate a central CFI Presentations account service or its own cloud database.

2. OpenAI API

When the user requests AI-assisted lesson analysis or generation, the relevant prompts, lesson inputs, and selected reference excerpts are sent to the OpenAI API using the API key configured by the user. OpenAI processes that information under its applicable API terms and privacy documentation. API usage may be billed separately by OpenAI. The application developer does not receive a copy of the user's API key through this website.

When the user chooses to generate a new slide illustration or restyle a found image, the slide title, teaching purpose, visual direction, relevant slide facts, optional prompt text, and the bundled transparent PNG style-reference examples are sent to the OpenAI Images API. For restyling, the selected source image is also sent to OpenAI so the image model can use it as a visual reference. These image-generation/edit requests may incur separate OpenAI API charges.

Image generation and restyling can be run manually one slide at a time, or automatically when the user explicitly enables Auto-build visuals in Generation Settings. In Auto mode, the application may choose a source image, send it to OpenAI for restyling, and/or generate an original illustration without a separate per-image confirmation. The user chooses a maximum number of AI image operations per lesson (0, 2, 4, 6, 8, or 12); one generation or one restyle counts as one operation. A setting of 0 disables automatic AI image-generation and restyling calls. The toggle is off by default. Generated/restyled images are saved locally in the application's media folder until the user publishes a presentation.

2A. Online media search

When online media discovery is enabled, the local application derives search terms from the lesson topic, slide visual direction, and opening-story script. It sends these search terms to Wikimedia Commons to find images and diagrams, and—if the user has configured a YouTube Data API key—to YouTube to find embeddable opening-hook videos. These searches return public search metadata such as titles, thumbnails, creator/channel names, source links, and licence information.

In review-first mode, candidates are displayed for the user's selection; an image is not downloaded and a video is not embedded until selected. If the user explicitly enables Auto-build visuals, the application may automatically select and download/import relevant Commons images and assign them to slides without per-item confirmation. It may also automatically select an embeddable YouTube video for the opening hook. The application does not download or re-upload YouTube videos. Online searches can be disabled independently; when disabled, Auto mode uses only relevant locally uploaded media and any enabled, budgeted AI image operations.

For Wikimedia Commons, the application offers only results that appear to carry public-domain, CC0, CC BY, or CC BY-SA reuse-friendly terms, and it retains the available creator, source, and licence information. The user remains responsible for reviewing the complete licence and meeting attribution or share-alike requirements. For YouTube, the application embeds the selected video from YouTube and records its title, channel, and URL in the slide's speaker notes; video availability and embedding remain subject to the creator's settings and YouTube's terms. The application selects existing videos; it does not generate new videos.

3. Google account and Google Slides

If the user chooses to connect Google Slides, the application uses Google's OAuth authorization flow. It requests these permissions:

  • https://www.googleapis.com/auth/presentations to create and edit Google Slides presentations.
  • https://www.googleapis.com/auth/drive.file to create and manage files created or opened by this application within Google Drive.

The application stores the OAuth client configuration and authorization token locally on the user's computer. The token is used to authenticate requests to Google's APIs. The application does not send the token to the website hosting this policy. The user can disconnect Google from within the application; the locally stored token is then removed. The user can also revoke the application's access through their Google Account security settings.

When the user publishes a lesson, the generated presentation content is sent to Google through the Slides and Drive APIs and saved in the user's Google Drive. Google's handling of that information is governed by Google's own terms and privacy policy.

Selected still images are included in the PowerPoint file sent to Google Drive for conversion into Google Slides. User-uploaded/local videos are uploaded to the user's Google Drive and inserted as Google Slides video elements. Selected YouTube videos are inserted into the presentation as native YouTube video elements and are not downloaded or re-uploaded. The application only sends selected media to Google when the user chooses to publish a presentation.

4. Information this website collects

This static GitHub Pages website is provided to display information about the application and this privacy policy. It does not contain an application login, analytics code, advertising trackers, contact form, or file-upload feature. GitHub may process standard technical request data as part of hosting the website; GitHub's privacy documentation applies to that hosting service.

5. Sharing and sale

The application developer does not operate a service that sells personal information or independently shares users' lesson data. Information is transmitted to OpenAI, Wikimedia Commons, YouTube, or Google only when the user enables or invokes the corresponding application feature, as described above. Automatic visual selection is only performed while the user has explicitly enabled Auto-build visuals; that setting authorizes the described searches, imports, and image-generation/restyling operations within the selected AI-operation cap. Those providers process information under their own applicable terms and policies.

6. Data retention and deletion

Local project files, reference documents, imported Wikimedia images and their attribution metadata, uploaded media, generated/restyled illustrations, the optional YouTube API key, settings, and OAuth tokens remain on the user's computer until the user deletes them or uses the application's available deletion or disconnect functions. Presentations created in Google Drive remain subject to the user's Google Drive settings and deletion actions. OpenAI, Wikimedia, and YouTube process requests under their respective applicable terms and privacy policies.

7. Security

Users are responsible for protecting their computer, local application folder, OpenAI API key, Google OAuth client JSON file, and locally stored Google authorization token. These credentials should not be shared or committed to a public source-code repository.

8. Changes to this policy

This policy may be updated when the application's features or data handling change. The revision date at the top of this page indicates the latest update.

9. Contact

For questions about this personal project, use the contact options available through the project owner's GitHub profile: github.com/chibibaka.

Important: This policy describes the local CFI Presentation Generator v23.0 workflow. It should be reviewed and updated if the application later adds cloud storage, telemetry, user accounts, remote processing, or other data flows.
